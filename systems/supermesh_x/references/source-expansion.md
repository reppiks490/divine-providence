# Source expansion universe

SuperMesh-X should be capable of expanding beyond any single search, crawler, or market-data provider by routing across independent source classes.

## Public web and discovery

- general web search engines
- AI-native search engines
- site-specific search
- sitemaps and RSS/Atom feeds
- public robots-permitted crawl paths
- public pages requiring browser rendering
- public documents, PDFs, filings, press releases, and investor-relations pages
- public archives and historical snapshots when legally accessible
- public code/docs ecosystems and package registries

## Structured and specialist data

- market feeds and reference data
- company fundamentals and statements
- macroeconomic and rates data
- earnings, dividends, splits, and corporate actions
- regulatory and exchange notices
- blockchain and smart-contract data
- public datasets and statistical portals
- scientific literature and citation graphs
- legal/regulatory corpora
- standards/specifications and technical documentation
- patent/public intellectual-property databases when available
- geospatial/public-government datasets when relevant

## User-authorized/private sources

- files and project knowledge
- connected drives/docs
- connected repositories
- connected databases/warehouses
- connected CRM/analytics systems
- meeting notes/transcripts
- email/calendar only when explicitly relevant and authorized

## Expansion strategy

The mesh should not blindly crawl everything. It should create a source graph from the request, rank source classes by expected information gain, and widen only when the answer remains uncertain, stale, disputed, or incomplete.

## High-value discovery behaviors

- discover canonical domains before crawling
- prefer APIs/feeds over scraping when equivalent structured data exists
- pivot from secondary sources to primary sources
- recursively follow citations/references within a bounded depth
- identify mirrors and syndication to avoid false corroboration
- detect newly surfaced entities and branch research only when they materially affect the question
- support incremental refreshes so repeated research does not re-fetch unchanged material unnecessarily
