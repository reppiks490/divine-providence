# SuperMesh-X v3.1 Durable Trust Root & Transparency Boundary

## Intent
Preserve the v3.0 signed-evidence boundary while making signer trust durable, sequentially rotatable, and externally auditable. A valid signature remains evidence authenticity only; it never grants execution authority.

## Design
1. **Durable trust policy** — versioned/epoched policy containing public Ed25519 keys and a signature threshold. The store serializes atomically and reloads without private material.
2. **Dual-threshold rotation** — epoch N+1 must be exactly sequential and the rotation statement must satisfy the trusted threshold from epoch N and the new threshold from epoch N+1, mirroring TUF's continuity principle. Rollback, skipped epochs, duplicate key IDs, and insufficient signatures fail closed.
3. **Transparency log** — canonical entries are committed to an RFC-6962-style Merkle tree. The reference log produces inclusion proofs and signed checkpoints. Checkpoints chain to the prior checkpoint digest and reject same-size conflicting roots or size rollback.
4. **Authority firewall** — trust-policy capabilities are not execution capabilities. No policy/signature/log receipt can manufacture broker, host-write, messaging, credential, or runtime-launch authority.
5. **Compatibility** — v3.0 `Ed25519Signer`, `TrustStore`, and `SignedEvidenceJournal` APIs remain unchanged.

## Error posture
Malformed policy, non-sequential rotation, threshold failure, bad inclusion proof, checkpoint rollback/equivocation, secret-bearing metadata, or private-key persistence fails closed. Missing external transparency providers fail open only for independent actions that do not require them.

## Tests
RED-first tests cover persistence/reload, dual-threshold rotation, rollback/skip rejection, Merkle inclusion/tamper detection, chained signed checkpoints, split-brain checkpoint rejection, authority non-escalation, and secret/private-key absence. Full regression and package gates follow.
