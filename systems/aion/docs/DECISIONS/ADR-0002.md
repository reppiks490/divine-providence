# ADR-0002 — Gap time and synthetic source inheritance

Date: 2026-09-23. Status: implemented in the research foundation.

## Decision

Persist sequence-gap and recovery transitions with their claimed availability times. Reconstruct the gap state at the replay time instead of reading only the ledger's current unresolved gaps. Require strictly later availability for each unsequenced revision. Reject corrections on sequenced streams until a provider-specific adapter defines correction sequence semantics. Require a contiguous policy for replayable depth.

Carry synthetic source origin into the frame and all four read-only exports, even when no scenario overlay is active. Keep `scenario` separate so a synthetic source observation can still be distinguished from an alternate timeline. The UI marks partial quality if true trade or depth evidence is absent and ignores responses from superseded scrub requests.

## Why

A current gap leaking into an earlier frame or a recovered gap disappearing from a past frame defeats decision-time reconstruction. A retroactively available revision has the same failure. A demo frame labeled nonsynthetic in an export could be mistaken for provider evidence. Request races could replace a newer scrub result with a stale one.

## Limits

The provider-recovery flag and timestamp remain adapter assertions. Real ingestion needs authenticated provider metadata, a trusted receipt clock and a complete coverage test. The event hash chain protects event records; gap transitions are append-only SQLite rows and have database immutability triggers, but are not independently signed. No existing external database was migrated.
