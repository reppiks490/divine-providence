# ARGUS load-stratified source-run cluster transfer

ARGUS now has a prospective paper-to-broker calibration audit that combines two
separate guardrails:

1. condition the comparison on requested-to-visible liquidity load;
2. resample complete `source_run_id` clusters rather than treating every fill
   as an independent bootstrap unit.

The implementation lives in
`argus.impact_calibration_load_cluster_transfer`.

## Why combine load bands and clusters

A row-wise load-stratified bootstrap can detect that paper execution becomes
optimistic at high liquidity load, but many fills from one source run may still
be correlated.

A global source-run cluster bootstrap guards against pseudoreplication, but can
average together low-load and high-load behavior.

The load-cluster audit requires both conditions simultaneously:

- paper and broker evidence are compared inside the same predeclared load band;
- uncertainty is generated by resampling whole eligible source-run clusters
  inside that band.

This can fail a high-load band while leaving a low-load band compatible, without
pretending fills from one run are independent experiments.

## Prospective plan

`argus-impact-calibration-load-cluster-transfer-plan-v1`
content-addresses:

- exact prospective impact-calibration study manifest ID;
- plan creation time;
- fixed cluster field `source_run_id`;
- exhaustive requested-to-visible load bands;
- exact metric set;
- tolerance for every load-band/metric pair;
- confidence alpha;
- deterministic cluster-bootstrap replicate count;
- deterministic bootstrap seed;
- minimum eligible source-run clusters required in each evidence class inside
  every load band;
- minimum eligible observations required in each evidence class inside every
  load band.

The plan cannot predate the referenced study manifest and must be registered
at or before the study cohort starts. This makes the declared plan chronology
internally consistent before any cohort outcome can be observed.

The study manifest must predeclare both:

- `BROKER_CONFIRMED`;
- `ICARUS_PAPER_EMULATOR`.

## Load partition

The load field is the existing calibration value:

```text
requested_to_visible_ratio
    = requested size / visible opposite-side size
```

Load bands must:

- begin at `0.0`;
- be contiguous;
- never overlap;
- have unique labels;
- use inclusive lower bounds;
- use exclusive finite upper bounds;
- leave only the final upper bound open.

At most twelve bands are permitted.

Every calibration row therefore maps to exactly one band.

## Fixed clustering field

Version 1 fixes the cluster field to the immutable execution receipt's
`source_run_id`.

The cluster field is not selected after results are visible.

Across the complete cohort within each evidence class, a reused
`source_run_id` must resolve to the same `source_system`, `source_repo`, and
`source_commit`. This validation happens before load-band partitioning, so a
run identifier cannot evade the lineage check by colliding only across different
load bands. A collision across execution-source lineage fails closed rather than
silently treating unrelated runs as one experimental cluster.

For each load band, evidence class and metric:

1. filter rows into the predeclared load band;
2. exclude rows ineligible for that metric;
3. group the remaining rows by `source_run_id`;
4. require the predeclared minimum clusters and observations;
5. independently resample complete paper and broker clusters with replacement;
6. preserve all eligible rows inside every selected cluster;
7. compute the requested calibration metric;
8. record the paper-minus-broker bootstrap distribution.

## Supported metrics

The first supported metrics are:

- `mean_fill_fraction_error`;
- `mean_absolute_fill_fraction_error`;
- `mean_slippage_error_ticks`;
- `mean_absolute_slippage_error_ticks`;
- `root_mean_squared_slippage_error_ticks`;
- `slippage_underprediction_rate`.

Fill-fraction metrics can use zero-fill rows.

Slippage metrics require realized slippage. A source run containing only
zero-fill rows does not become an invented slippage cluster.

## Deterministic resampling

The initial state for every
evidence-kind/load-band/metric/replicate is derived from SHA-256 of:

```text
bootstrap_seed
| load-cluster-transfer
| source_run_id
| evidence_kind
| band_label
| metric
| replicate
```

A fixed 64-bit linear congruential transition chooses cluster indices.

The method identifier is:

`deterministic_load_stratified_two_sample_cluster_percentile`

## Comparison

For each load-band/metric pair:

```text
paper_minus_broker = paper estimate - broker estimate
```

ARGUS reports:

- load-band bounds;
- metric name;
- paper and broker point estimates;
- paper-minus-broker estimate;
- percentile lower and upper bounds;
- confidence level and alpha;
- paper and broker eligible cluster counts;
- paper and broker eligible observation counts;
- predeclared tolerance;
- compatibility outcome.

The two evidence classes are never pooled.

## Pseudoreplication guardrail inside each load band

The plan separately requires:

- `min_clusters_per_kind_per_band`;
- `min_metric_observations_per_kind_per_band`.

Many fills from one low-load broker run do not satisfy the minimum broker
cluster count for that load band.

This is stricter than either row-wise load stratification or global cluster
resampling alone.

## Tolerance gate

A band/metric result reports `within_tolerance=true` only when the entire
cluster-bootstrap interval lies inside:

```text
[-tolerance, +tolerance]
```

The aggregate result passes only when every predeclared load-band/metric pair
passes.

## Interpretation boundary

This analysis is not automatically:

- a formal equivalence test;
- a proof that `source_run_id` captures every dependence structure;
- a proof that requested-to-visible ratio captures every execution regime;
- a small-sample-valid cluster theorem;
- a multiplicity-adjusted familywise statement;
- a causal-effect estimate;
- proof of queue priority, hidden-liquidity, routing, or latency realism;
- proof of profitability;
- permission to relabel paper fills as broker-confirmed;
- permission to substitute paper evidence for broker evidence;
- permission to place an order.

If dependence spans source runs or execution quality depends on additional
predecision covariates, those require separately predeclared protocols.

## Validation before resampling

ARGUS revalidates:

- prospective study manifest identity;
- locked cohort identity;
- execution-evidence receipts;
- receipt-plus-calibration lineage;
- exact source revisions;
- cohort timing and observation cutoff;
- snapshot-age and completion-latency limits;
- load-cluster plan identity;
- prospective plan creation time;
- exhaustive load partition;
- cluster field;
- metric/tolerance matrix;
- cluster and observation minimums in every band;
- authority flags.

Tampering fails closed before bootstrap work begins.

## Computational boundary

Version 1 permits:

- 200 through 10,000 bootstrap replicates;
- at most twelve load bands.

This is offline research. It does not execute on the ICARUS live decision hot
path.

## Authority

`execution_authorized=false`

`production_decision_authorized=false`

Passing every load-cluster tolerance does not authorize model promotion or a
broker order.
## Research export contract

`argus.impact_calibration_load_cluster_transfer_research_export` provides
`argus-impact-calibration-load-cluster-transfer-research-v1`.

Before export, ARGUS recomputes the registered load-stratified source-run
cluster transfer audit.

The export preserves:

- study manifest and locked cohort IDs;
- load-cluster transfer plan ID and schema;
- fixed cluster field `source_run_id`;
- exhaustive load-band definitions;
- exact impact-model, calibration and execution-source revisions;
- metric set and per-band/per-metric tolerances;
- confidence alpha, deterministic seed and bootstrap replicate count;
- predeclared minimum cluster and observation counts;
- paper and broker eligible cluster counts;
- paper and broker eligible observation counts;
- paper-minus-broker point estimates and cluster-bootstrap intervals;
- aggregate and per-band compatibility outcomes;
- explicit non-promotion and authority flags.

The envelope explicitly states:

- `formal_equivalence_test=false`;
- `multiplicity_adjusted=false`;
- `familywise_coverage=false`;
- `causal_effect_estimate=false`;
- `paper_evidence_promoted=false`;
- `broker_substitution_authorized=false`.

Publication cannot precede the locked study cohort. Downstream local
availability must still wait for ingestion time.

## ATHENA integration status

The export contract is transport-ready, but the deterministic hub still lacks a
genuine broker-confirmed execution fixture with externally valid lineage.

No ATHENA happy-path driver fabricates broker-confirmed fills merely to make the
cross-system path appear complete.

Synthetic broker-confirmed objects remain confined to isolated unit tests of
the contract path and are not emitted as empirical ATHENA advisory evidence.

This preserves both the execution-evidence firewall and the load-conditioned
pseudoreplication guardrail.
