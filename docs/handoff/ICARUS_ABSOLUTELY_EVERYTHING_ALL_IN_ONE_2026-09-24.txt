- audit
- collapse to one canonical observation

- hard reject

1. instrument semantic compatibility
2. timestamp/freshness compatibility
3. market-state comparability

Then compute disagreement/dispersion.

Provider disagreement can only reduce authority, never increase it.

`available_at >= received_at`

Staleness increases => authority cap cannot increase.

## Bar completion evidence loss — P0
`icarus_engine.pine.timeframe.Bar` stores:
- ts (bar OPEN)
- OHLCV

It does not store:
- nominal/effective bar close time
- actual completion time
- time ICARUS observed the bar as closed

`Aggregator` internally knows `_end()` and can close bars in multiple ways:
1. when a sub-bar ends at the bucket boundary,
2. when the first sub-bar of a new bucket causes the previous bucket to close,
3. via `flush_if_stale(now_ts, grace)` after wall-clock time passes the expected end.

Therefore these times are distinct:
- bar_open_time
- nominal/effective_close_time
- observed_complete_at / feature_available_time

The current `Bar` object loses this distinction once `_close()` returns a Bar.

This is a P0 temporal issue because completed OHLC features cannot safely use bar OPEN time as their availability time.

### Required fix
Add temporal metadata outside or alongside raw market `Bar`:
- open_time
- effective_close_time
- completed_at
- available_at

Do not mutate a raw price bar into an execution-authority object without provenance.

For clock bars:
`available_at >= completed_at >= effective_close_time`

When a bar closes late because a boundary sub-bar was missing, `completed_at` may be later than nominal close.

For session-truncated bars, `end_fn` can make close time differ from `open + nominal_duration`.

## Irregular bars

Do not infer completion time from a duration for:
- Renko

Missing explicit completion/availability timestamp:

## FOMC fallback timing defect — P0
Current `KIND_HOUR_UTC["fomc"] = 18` and `seed_events()` assigns all FOMC decisions at 18:00 UTC.

Official 2026 Federal Reserve statements show:
- Jan 28, 2026 released at 2:00 p.m. EST = 19:00 UTC
- summer/September releases at 2:00 p.m. EDT = 18:00 UTC

Therefore fixed 18:00 UTC makes winter FOMC fallback events one hour early.

Required:
Store release time in America/New_York or explicit timezone-aware datetime and convert per event date.
Do not encode U.S. Eastern economic events using one constant UTC hour across DST.

## CPI / PPI / NFP / PCE / GDP timing defect — P0
Current event fallback table uses whole UTC hours such as 12 for several U.S. releases.

Official BLS and BEA schedules use 8:30 a.m. Eastern for key releases including:
- CPI
- Employment Situation
- Personal Income and Outlays / PCE
- many GDP releases

Therefore the current fallback:
- loses the :30 minute
- ignores DST
- can be wrong by 30 to 90 minutes depending on date

Required EventObservation fields:
- scheduled_for timezone-aware timestamp
- schedule_known_at
- result_available_at
- received_at
- provider/source
- revision/version identity

If only a date is known and exact release time is not sourced:
do not invent one.
